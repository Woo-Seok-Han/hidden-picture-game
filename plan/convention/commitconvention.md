# Commit Convention

프로젝트의 커밋 이력을 일관되고 이해하기 쉽게 유지하기 위한 규칙입니다.

## 1. 기본 형식

커밋 메시지는 다음 형식을 사용합니다.

```text
<type>(<scope>): <subject>
```

`scope`는 변경 범위를 명확하게 설명할 때만 사용하며 생략할 수 있습니다.

```text
feat(player): 게임 결과 화면 추가
fix(admin): 정답 영역 좌표 계산 오류 수정
docs: 커밋 컨벤션 문서 작성
```

## 2. Type

| Type | 용도 |
| --- | --- |
| `feat` | 새로운 기능 또는 화면 추가 |
| `fix` | 버그 수정 |
| `refactor` | 기능 변경 없는 코드 구조 개선 |
| `style` | 포맷, 공백, 세미콜론 등 동작에 영향 없는 변경 |
| `docs` | 문서 추가 또는 수정 |
| `test` | 테스트 추가 또는 수정 |
| `chore` | 설정, 패키지, 빌드 작업 등 기타 변경 |
| `perf` | 성능 개선 |
| `build` | 빌드 시스템 또는 외부 의존성 변경 |
| `ci` | CI 설정 및 스크립트 변경 |
| `revert` | 이전 커밋 되돌리기 |

## 3. Scope

`scope`는 변경된 앱이나 주요 기능 영역을 소문자로 작성합니다.

권장 scope:

| Scope | 대상 |
| --- | --- |
| `player` | 참여자 게임 화면과 게임 흐름 |
| `admin` | 관리자 화면과 문제 관리 기능 |
| `question` | 문제 및 정답 영역 도메인 |
| `assets` | 이미지, 아이콘 등 정적 자산 |
| `config` | 프로젝트 설정 |

적절한 scope가 없거나 변경 범위가 프로젝트 전체라면 생략합니다.

## 4. Subject 작성 규칙

- 변경 내용을 한 문장으로 간결하게 작성합니다.
- `type`과 `scope`는 영문 소문자를 사용합니다.
- 제목은 한국어 작성을 기본으로 합니다.
- 제목 끝에 마침표를 사용하지 않습니다.
- `수정`, `변경`, `작업`처럼 범위가 불명확한 표현만 단독으로 사용하지 않습니다.
- 구현한 내용보다 변경의 목적과 결과가 드러나도록 작성합니다.
- 한 커밋에는 하나의 논리적인 변경만 포함합니다.

좋은 예:

```text
feat(player): 5문제 순차 진행 기능 추가
fix(player): 완료 화면 배경 중복 노출 수정
refactor(player): 화면별 컴포넌트 분리
docs: 코드 컨벤션 보완
```

피해야 할 예:

```text
update
수정
feat: 여러 가지 변경
Fix Bug.
```

## 5. 본문과 Footer

제목만으로 변경 이유를 설명하기 어려울 때 본문을 작성합니다. 제목과 본문 사이에는 빈 줄을 둡니다.

```text
fix(player): 문제 전환 중 중복 입력 방지

답안 처리 중 버튼과 이미지가 다시 선택되는 문제를 막기 위해
제출 상태에서는 입력 요소를 비활성화한다.
```

이슈를 연결할 때는 Footer에 작성합니다.

```text
Closes #12
Refs #8
```

## 6. Breaking Change

기존 API나 데이터 구조와 호환되지 않는 변경은 type 뒤에 `!`를 붙이고 Footer에 내용을 설명합니다.

```text
feat(question)!: 정답 영역 좌표 형식 변경

BREAKING CHANGE: 픽셀 좌표를 0부터 1 사이의 정규화 좌표로 변경한다.
```

## 7. 커밋 단위

- 서로 독립적으로 되돌릴 수 있는 변경은 별도 커밋으로 나눕니다.
- 기능 코드와 무관한 포맷 변경을 한 커밋에 섞지 않습니다.
- 빌드 또는 테스트가 실패하는 중간 상태는 커밋하지 않습니다.
- 생성 파일과 임시 파일은 필요한 경우에만 포함합니다.
- 커밋 전 변경 파일과 diff를 확인합니다.

## 8. 커밋 전 체크리스트

- [ ] 변경 내용이 하나의 목적을 갖는가?
- [ ] 올바른 type과 scope를 사용했는가?
- [ ] 제목만 읽어도 변경 내용을 이해할 수 있는가?
- [ ] 관련 없는 파일이 포함되지 않았는가?
- [ ] 린트, 테스트 또는 빌드 검증을 통과했는가?
- [ ] 비밀번호, 토큰 등 민감한 정보가 포함되지 않았는가?
