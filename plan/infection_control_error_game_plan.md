# 감염관리 오류 찾기 GAME --- MVP 기획서

## 1. 프로젝트 개요

### 1.1 목적

감염관리 행사 부스에서 간호사를 대상으로 진행하는 참여형 교육 게임이다.

참여자는 실제 간호 업무 환경과 유사한 사진을 보고 **감염관리 관점에서
잘못된 물품 보관 상태를 찾아내거나, 오류가 없는 사진이라고 판단**한다.

게임 종료 후 자신이 풀었던 문제와 정답 및 해설을 확인하여 단순 이벤트
참여를 넘어 감염관리 교육 효과를 제공한다.

### 1.2 운영 환경

-   감염관리 행사 부스
-   주요 참여자: 간호사
-   1차 기준 디바이스: 태블릿
-   추가 지원: 행사장 모니터/PC
-   화면 방향: 태블릿 가로형 우선
-   반응형 웹으로 구현하여 다양한 화면 크기 지원

------------------------------------------------------------------------

## 2. MVP 범위

### 2.1 필수 기능

1.  사번 입력
2.  등록된 문제 사진 중 랜덤 출제
3.  사진에서 오류 위치 찾기
4.  `오류 없음` 선택
5.  문제별 타이머
6.  사진 1장당 오류는 `1개 또는 없음`
7.  게임 종료 결과 표시
8.  출제되었던 사진 목록 표시
9.  문제별 정답 및 해설 표시
10. 관리자 문제 사진 업로드
11. 관리자 문제별 제한시간 설정
12. 문제별 오류 개수 설정
13. 이미지 미리보기에서 드래그하여 정답 영역 지정
14. 문제별 해설 등록

### 2.2 MVP에서 제외

-   회원가입
-   일반 로그인
-   점수 시스템
-   랭킹
-   별점
-   힌트
-   스테이지 선택
-   난이도 선택
-   캐릭터/수집 요소
-   복잡한 통계 기능

## 3. 게임 기본 규칙

### 3.1 문제 구성

문제 하나는 사진 한 장으로 구성한다.

각 사진의 정답 유형은 아래 둘 중 하나다.

#### 유형 A --- 오류 있음

-   사진 안에 잘못된 부분이 정확히 1개 존재한다.
-   사용자가 사진에서 해당 위치를 터치한다.

#### 유형 B --- 오류 없음

-   사진 안에 감염관리상 잘못된 부분이 없다.
-   사용자가 `오류 없음` 버튼을 선택한다.

따라서 한 사진에 여러 개의 오류를 숨기지 않는다.

### 3.2 출제 방식

관리자가 등록한 활성 문제 중 게임 시작 시 문제를 랜덤으로 선택한다.

초기 권장 출제 수:

**1게임 = 랜덤 5문제**

출제 문제 수는 향후 설정값으로 변경 가능하도록 구현한다.

### 3.3 타이머

각 문제에는 해당 문제에 설정된 제한시간을 적용한다.

초기 권장값:

**문제당 20초**

화면 상단에 남은 시간을 표시한다.

예:

`문제 2 / 5        00:14`

관리자는 문제를 등록하거나 수정할 때 제한시간을 초 단위로 설정한다.
문제마다 서로 다른 제한시간을 가질 수 있으며 초기 입력값은 20초를
권장한다.

### 3.4 사용자 답변

사용자가 할 수 있는 답변은 두 가지다.

**오류가 있다고 판단** - 사진의 특정 위치를 터치한다.

**오류가 없다고 판단** - `오류 없음` 버튼을 누른다.

## 5. 화면 기획

## 5.1 입장 화면

### 목적

-   참여자 식별
-   게임 시작

### 구성

``` text
┌───────────────────────────────────────────┐
│                                           │
│          감염관리 오류 찾기 GAME           │
│                                           │
│       사진 속 잘못된 부분을 찾아보세요!     │
│                                           │
│            사번을 입력하세요               │
│       ┌──────────────────────┐            │
│       │                      │            │
│       └──────────────────────┘            │
│                                           │
│              [ 게임 시작 ]                 │
│                                           │
│         사번 입력 후 게임을 시작하세요.      │
│                                           │
└───────────────────────────────────────────┘
```

### 동작

1.  사용자가 사번 입력
2.  게임 시작 버튼 클릭
3.  입력값이 비어 있지 않은지만 확인
4.  서버에서 새로운 게임 세션 생성
5.  게임 시작

MVP에서는 사번 자릿수와 문자 형식에 대한 유효성 검사를 적용하지 않는다.
동일한 사번으로 여러 번 참여할 수 있으며, 각 참여는 별도의 게임 세션으로
저장한다.

## 5.2 게임 화면

### 기본 구성

``` text
┌─────────────────────────────────────────────────────┐
│ 문제 1 / 5        잘못된 부분을 터치하세요   00:18 │
├─────────────────────────────────────────────────────┤
│                                                     │
│                                                     │
│                                                     │
│                   문제 사진                         │
│                                                     │
│                                                     │
│                                                     │
├─────────────────────────────────────────────────────┤
│                                                     │
│                   [ 오류 없음 ]                     │
│                                                     │
└─────────────────────────────────────────────────────┘
```

### 표시 정보

-   현재 문제 번호
-   전체 문제 수
-   남은 시간
-   문제 사진
-   `오류 없음` 버튼

### 오류가 있는 경우

사용자가 사진을 터치한다.

클릭 좌표가 관리자가 등록한 정답 영역 안에 포함되는지 판정한다.

### 오류가 없는 경우

사용자가 `오류 없음` 버튼을 선택한다.

------------------------------------------------------------------------

## 5.3 정답 판정

사용자가 답변하면 해당 문제의 결과를 저장한다.

저장 정보 예시: - 문제 ID - 사용자가 선택한 답변 - 사용자가 터치한
좌표 - 정답 여부 - 응답 시간

정답/오답 피드백은 짧게 표시한 뒤 다음 문제로 이동한다.

예:

``` text
✓ 정답입니다!
```

또는

``` text
✕ 아쉽습니다.
```

상세한 교육 해설은 게임 종료 후 결과 화면에서 제공한다.

------------------------------------------------------------------------

## 5.4 게임 완료 화면

모든 문제를 완료하면 결과 요약을 표시한다.

``` text
┌───────────────────────────────────────────┐
│                                           │
│                 게임 완료!                │
│                                           │

│                                           │
│                 총 문제 5                 │
│                  정답 4                   │
│                  오답 1                   │
│                                           │
│             [ 결과 확인하기 ]              │
│                                           │
└───────────────────────────────────────────┘
```

## 5.5 결과 및 해설 화면

교육 효과를 위해 사용자가 실제로 풀었던 문제를 다시 보여준다.

### 상단

-   정답 수
-   오답 수
-   정답률
-   총 소요시간

### 문제별 표시 정보

각 문제마다 다음 정보를 제공한다.

-   문제 번호
-   출제 사진
-   사용자 선택
-   실제 정답
-   정답/오답 여부
-   오류가 있는 경우 정답 위치 표시
-   문제 해설

### 예시

``` text
1. 처치 카트                           ✓ 정답

┌─────────────────┐
│                 │
│    문제 사진     │     당신의 선택 : 오류 있음
│       ○         │     정답        : 오류 있음
│                 │
└─────────────────┘

[해설]

손소독제가 오염 가능성이 있는 위치에
보관되어 있습니다.

적절한 위치에 보관해야 합니다.
```

오류가 없는 문제:

``` text
2. 물품 보관장                         ✕ 오답

┌─────────────────┐
│                 │
│    문제 사진     │     당신의 선택 : 오류 있음
│                 │     정답        : 오류 없음
│                 │
└─────────────────┘

[해설]

해당 사진의 물품들은 적절한 위치와
방법으로 보관되어 있습니다.
```

### 하단

`처음으로 돌아가기`

행사 부스 운영을 고려하여 다음 참가자가 바로 사용할 수 있도록 초기 사번
입력 화면으로 이동한다. 결과 화면에는 `다시 참여하기` 버튼을 두지 않는다.
동일한 사번으로 다시 참여하려면 초기 화면에서 사번을 다시 입력한다.

## 6. 관리자 기능

관리자 화면에서는 행사 운영에 필요한 문제와 게임 설정을 관리한다.

관리자 화면의 핵심 목적은 아래 네 가지다.

1. 문제 사진 업로드
2. 문제별 오류 개수 설정
3. 이미지 미리보기에서 오류 위치 지정
4. 문제별 제한시간 설정

---

## 6.1 관리자 대시보드

관리자 진입 후 가장 먼저 보여주는 화면이다.

### 주요 메뉴

```text
┌──────────────────────────────────────────────────────────────┐
│ 감염관리 오류 찾기 GAME 관리자                              │
├──────────────────┬───────────────────────────────────────────┤
│                  │                                           │
│  게임 설정       │        관리자 메인 영역                  │
│                  │                                           │
│  문제 관리       │                                           │
│                  │                                           │
│  문제 등록       │                                           │
│                  │                                           │
│  참여 현황       │                                           │
│                  │                                           │
└──────────────────┴───────────────────────────────────────────┘
```

MVP에서는 관리자 기능을 복잡하게 만들지 않고 아래 메뉴를 중심으로 구성한다.

- 게임 설정
- 문제 목록
- 문제 등록/수정
- 참여자 확인

---

## 6.2 게임 설정

행사 운영자가 코드 수정 없이 게임 진행 조건을 변경할 수 있도록 한다.

### 설정 가능 항목

#### 게임당 출제 문제 수

예:

```text
게임당 출제 문제 수

[ 5 ] 문제
```

관리자가 등록된 활성 문제 중 몇 장을 랜덤으로 출제할지 설정한다.

예:
- 3문제
- 5문제
- 10문제

### 설정 화면 예시

```text
┌──────────────────────────────────────────────┐
│ 게임 설정                                    │
├──────────────────────────────────────────────┤
│                                              │
│ 게임당 출제 문제 수                          │
│ [ 5 ] 문제                                   │
│                                              │
│                         [ 설정 저장 ]         │
│                                              │
└──────────────────────────────────────────────┘
```

제한시간은 공통 게임 설정이 아니라 각 문제의 등록/수정 화면에서 설정한다.

---

## 6.3 문제 목록

관리자가 등록된 문제 사진을 조회하고 수정/삭제할 수 있다.

### 표시 정보

- 문제 ID
- 이미지 썸네일
- 문제 제목
- 오류 개수
- 오류 없음 여부
- 활성 여부
- 등록일
- 수정
- 삭제

### 화면 예시

```text
┌─────────────────────────────────────────────────────────────┐
│ 문제 관리                              [ + 문제 등록 ]      │
├────┬──────────┬──────────┬────────┬────────┬───────────────┤
│ ID │ 이미지    │ 제목      │ 오류수 │ 상태    │ 관리          │
├────┼──────────┼──────────┼────────┼────────┼───────────────┤
│ 1  │ [썸네일] │ 처치 카트 │ 1      │ 활성    │ 수정 / 삭제   │
│ 2  │ [썸네일] │ 보관장    │ 0      │ 활성    │ 수정 / 삭제   │
│ 3  │ [썸네일] │ 준비대    │ 1      │ 비활성  │ 수정 / 삭제   │
└────┴──────────┴──────────┴────────┴────────┴───────────────┘
```

## 6.5 사진 업로드

관리자가 문제로 사용할 사진을 업로드한다.

### 입력 항목

```text
문제 제목
사진 파일
오류 개수
제한시간
해설
활성 여부
```

### 화면 예시

```text
┌──────────────────────────────────────────────────────────────┐
│ 문제 등록                                                    │
├──────────────────────────────────────────────────────────────┤
│ 문제 제목                                                    │
│ [ 처치 카트 물품 보관                                       ]│
│                                                              │
│ 사진                                                         │
│ [ 파일 선택 ]                                                │
│                                                              │
│ 오류 개수                                                    │
│ [ 1 ▼ ]                                                      │
│                                                              │
│   0 = 오류 없음                                              │
│   1 이상 = 지정한 개수만큼 오류 영역 등록                    │
│                                                              │
│ 제한시간                                                     │
│ [ 20 ] 초                                                    │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

이미지는 서버 또는 이미지 스토리지에 저장하고 DB에는 이미지 URL을 저장한다.

## 6.6 오류 개수 설정

기존 MVP에서는 사진 한 장당 `오류 1개 또는 오류 없음`을 기본 규칙으로 한다.

다만 관리자 화면에서는 향후 확장 가능성을 고려해 **오류 개수 값을 설정할 수 있도록 데이터 구조를 설계**한다.

초기 운영 권장 범위:

```text
0 = 오류 없음
1 = 오류 1개
```

관리자 UI에서는 숫자를 선택한다.

예:

```text
오류 개수

[ 1 ▼ ]

0 : 오류 없음
1 : 오류 1개
```

향후 필요하면 2개 이상도 지원할 수 있도록 DB와 정답 영역 구조는 복수 등록이 가능하게 설계한다.

## 6.7 이미지 미리보기 및 정답 영역 지정

사진 업로드 후 같은 화면에서 이미지 미리보기를 보여준다.

관리자는 이미지 위에서 마우스 또는 터치로 **드래그하여 오류 영역을 지정**한다.

### 사용 흐름

```text
사진 업로드
    ↓
미리보기 표시
    ↓
[정답 영역 추가]
    ↓
사진 위에서 드래그
    ↓
사각형 영역 생성
    ↓
영역 저장
```

### 화면 예시

```text
┌──────────────────────────────────────────────────────────────┐
│ 이미지 미리보기                                             │
│                                                              │
│  ┌──────────────────────────────────────────────────────┐   │
│  │                                                      │   │
│  │                                                      │   │
│  │                   문제 사진                          │   │
│  │                              ┌────────────┐          │   │
│  │                              │ 정답 영역 1 │          │   │
│  │                              └────────────┘          │   │
│  │                                                      │   │
│  └──────────────────────────────────────────────────────┘   │
│                                                              │
│  [ + 정답 영역 추가 ]                                        │
│                                                              │
│  등록된 영역                                                  │
│  1. 오류 영역 1                         [삭제]                 │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

### 드래그 동작

관리자가 이미지에서 마우스를 누르고 드래그하면 사각형이 생성된다.

예:

```text
시작점
  ↓
  ┌────────────────┐
  │                │
  │   오류 영역     │
  │                │
  └────────────────┘
                  ↑
                종료점
```

정답 영역은 다음 값으로 저장한다.

```text
x
y
width
height
```

좌표는 px이나 `0~100` 퍼센트 값이 아니라 이미지 전체 크기를 `1`로 본
`0~1` 정규화 값으로 저장한다.

예:

```json
{
  "x": 0.625,
  "y": 0.248,
  "width": 0.082,
  "height": 0.124
}
```

이 방식으로 저장하면 태블릿, PC, 모니터에서 이미지가 다른 크기로 표시되어도 같은 위치를 정답으로 판정할 수 있다.

---

## 6.8 오류 영역 수정 및 삭제

등록된 정답 영역은 저장 전에 다시 수정할 수 있어야 한다.

지원 기능:

- 영역 선택
- 드래그하여 위치 이동
- 모서리 핸들을 이용한 크기 조절
- 영역 삭제
- 영역 다시 생성

예:

```text
┌────────────────────┐
│                    │
│    정답 영역        │
│                    │
└────────────────────┘
 ↑                  ↑
크기 조절 핸들
```

## 6.9 해설 등록

각 문제에는 결과 화면에서 보여줄 해설을 입력한다.

### 오류가 있는 문제 예시

```text
손소독제가 오염 가능성이 높은 위치에 보관되어 있습니다.
손 위생 물품은 오염 위험이 적고 쉽게 사용할 수 있는 위치에
보관해야 합니다.
```

### 오류가 없는 문제 예시

```text
사진 속 물품들은 감염관리 기준에 맞게 적절한 위치에
보관되어 있습니다.
```

오류가 여러 개로 확장되는 경우를 고려하여 정답 영역별 해설을 별도로 저장할 수 있도록 설계하는 것이 좋다.

## 6.10 문제 저장

문제를 저장하기 전에 아래 항목을 검증한다.

### 오류 개수 = 0
- 정답 영역이 없어야 한다.
- 해설이 입력되어 있어야 한다.

### 오류 개수 = 1 이상
- 설정한 오류 개수만큼 정답 영역이 존재해야 한다.
- 해설이 입력되어 있어야 한다.

검증 완료 후 저장한다.

```text
[ 임시 취소 ]                   [ 문제 저장 ]
```

## 6.11 관리자 문제 수정

이미 등록된 문제도 동일한 편집 화면에서 수정할 수 있다.

수정 가능 항목:

- 문제 제목
- 문제 사진 교체
- 오류 개수
- 정답 영역

- 해설
- 활성/비활성

이미지를 교체할 경우 기존 정답 좌표는 초기화하고 다시 지정하도록 한다.

행사 운영 중 참여 기록을 확인하기 위한 최소 화면을 제공한다.

표시 정보:

- 사번
- 참여 상태
- 시작 시각
- 완료 시각

예:

```text
┌───────────────────────────────────────────────────┐
│ 참여 현황                                          │
├──────────┬────────────┬────────────┬──────────────┤
│ 사번      │ 상태        │ 시작        │ 완료          │
├──────────┼────────────┼────────────┼──────────────┤
│ 123456   │ COMPLETED  │ 13:02      │ 13:04        │
│ 234567   │ PLAYING    │ 13:05      │ -            │
└──────────┴────────────┴────────────┴──────────────┘
```

MVP에서는 복잡한 통계 기능은 포함하지 않는다.

## 7. 데이터 모델 초안

### 7.1 Problem

``` text
id
title
imageUrl
hasError
errorCount
timeLimitSeconds
explanation
active
createdAt
updatedAt
```

`hasError = false`인 경우 `errorCount`는 0이고 연결된 정답 영역이 없어야
한다. MVP에서는 `errorCount`를 0 또는 1로 제한하되 향후 복수 오류로
확장할 수 있도록 한다.

### 7.2 AnswerArea

``` text
id
problemId
x
y
width
height
explanation
createdAt
updatedAt
```

하나의 문제는 여러 `AnswerArea`를 가질 수 있다. 좌표와 크기는 모두
`0~1` 범위의 정규화 값으로 저장한다. 문제 공통 해설은 `Problem`에,
향후 복수 오류에서 사용할 영역별 해설은 `AnswerArea.explanation`에
저장할 수 있다.

### 7.3 Participant

``` text
id
employeeNumber
completed
startedAt
completedAt
```

사번에는 유일 제약을 두지 않는다. 동일한 사번의 참여 기록을 허용하며
각 참여 시도는 새로운 참가 기록 및 게임 세션으로 저장한다. MVP에서는
사번 값이 비어 있는지만 검사하고 자릿수나 문자 형식은 검사하지 않는다.

### 7.4 GameSession

``` text
id
participantId
startedAt
completedAt
totalQuestions
correctCount
```

### 7.5 GameAnswer

``` text
id
gameSessionId
problemId
questionOrder
selectedType
selectedX
selectedY
correct
responseTime
```

이를 통해 결과 화면에서 사용자가 실제로 풀었던 문제와 답변을 그대로
재구성할 수 있다.

------------------------------------------------------------------------


### 7.6 GameSetting

```text
id
questionsPerGame
updatedAt
```

관리자 화면에서 게임당 출제 문제 수를 저장한다. 제한시간은
`Problem.timeLimitSeconds`에 문제별로 저장한다.

## 8. 참여 처리 정책

동일한 사번의 중복 참여를 허용한다. 사번은 참여 기록을 구분하고 행사 후
결과를 확인하기 위한 식별값으로 사용한다.

게임 시작 버튼을 눌렀다고 바로 `참여 완료` 처리하지 않는다.

권장 상태:

``` text
READY
  ↓
PLAYING
  ↓
COMPLETED
```

정상적으로 마지막 문제까지 완료한 시점에 `COMPLETED` 처리한다.

단, 행사 중 브라우저 종료나 태블릿 장애가 발생할 수 있으므로 `PLAYING`
상태 기록은 미완료 참여로 남긴다. 다시 시작하면 기존 세션을 이어가지 않고
새 게임 세션을 생성한다.

## 9. 반응형 설계

### 9.1 태블릿

MVP의 최우선 대상이다.

표시

동일한 게임 컴포넌트를 사용한다.

레이아웃

### 9.3 모바일

기술적으로 반응형을 지원하되 행사 MVP의 최우선 대상은 아니다.

## 13. MVP 완료 기준

``` text
관리자가 게임당 출제 문제 수를 설정한다.
        ↓
문제 사진을 업로드한다.
        ↓
문제별 오류 개수를 설정한다.
        ↓
문제별 제한시간을 설정한다.
        ↓
이미지 미리보기에서 드래그하여 정답 영역을 지정한다.
        ↓
해설을 입력한다.
        ↓
참가자가 사번을 입력한다.
        ↓
랜덤 문제를 출제한다.
        ↓
제한시간 내 사진에서 오류를 찾거나

        ↓
모든 문제를 완료한다.
        ↓
결과와 자신이 풀었던 사진을 확인한다.
        ↓
각 문제의 정답 위치와 해설을 확인한다.
        ↓
처음으로 돌아가 다음 참여를 시작할 수 있다.
```

## 14. 핵심 원칙

> **행사장에서 설명 없이도 바로 플레이할 수 있을 만큼 단순하게 만든다.**

게임 중 필요한 핵심 행동은 두 가지뿐이다.

1.  잘못된 부분 터치
2.  오류가 없다면 `오류 없음` 선택

교육 정보는 게임 진행을 방해하지 않도록 마지막 결과 및 해설 화면에
집중해서 제공한다.
